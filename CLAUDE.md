# VIA Bar — памятка для Claude

Читай целиком перед работой. Здесь всё, что нужно, чтобы продолжить проект в новом чате.

## Кто и что

- **VIA Bar** («VIA Family Bar») — домашний бар Владимира и Анастасии Шульминых.
- Сайт: https://shulya.party. Это два приложения, которые ставятся на экран «Домой» iPhone:
  - `/menu` — приложение гостя: меню, заказ (`#order`), профиль (`#profile`);
  - `/bar` — панель бармена: заказы, рецепты, склад, закупки. В разделе «Ещё»: ингредиенты, статистика, отзывы, фото, уведомления, безопасность.
- Пользователь — Владимир. Пишет по-русски и не программист.

## Как работать с Владимиром

- **Как общаться:**
  - Отвечать по-русски, просто, без жаргона.
  - По ходу работы коротко говорить, что сейчас делаешь.
- **Обычный цикл изменений:**
  1. Ветка, затем PR.
  2. Проверка: `node --check`, локальный запуск, скриншоты Playwright на 390×844.
  3. Squash-merge, когда Владимир поручил.
  4. Выкладка идёт сама.
  5. Проверка живого сайта.
  6. Отчёт по-русски.
- **Живой сайт проверяем только чтением** (GET). Никаких POST/PUT/DELETE на проде.
- **Тексты для гостей:**
  - пишем от «мы»;
  - слово «хозяева» не используем;
  - подпись «by Vladimir & Anastasia»;
  - «Карта гостя», а не «клубная»;
  - бар не «знает» сам: пишем «…и мы будем знать, кому нести коктейль».
- **Работа над дизайном:** «в коде ничего не меняй» значит только макеты и картинки, сайт не трогать.
- **Секреты:**
  - Репозиторий **публичный**: никаких ключей, кодов и данных гостей в коммитах, логах Actions и артефактах.
  - Ключ восстановления бармена есть только у Владимира. В коде хранится лишь его SHA-256.

## Устройство

- **Cloudflare Worker `bar-menu`** (`wrangler.toml`):
  - `src/worker.js` — вход, маршруты страниц, офлайн, cron;
  - `src/index.js` — API, схема базы и миграции, логика заказов, склада и фото;
  - `src/design.js` — общий каркас страниц и стили;
  - `src/barauth.js` — вход в панель по коду бармена;
  - `src/push.js` — уведомления Web Push.
- **База D1 `bar-menu-db`:**
  - Схему создаёт и обновляет сам Worker: `ensureSchema`, таблица `app_migrations`, `SCHEMA_VERSION` в `src/index.js`. Пустая база поднимается с нуля: основные таблицы (`cocktails`, `products`, `recipe_items`, `purchase_batches`) тоже в `SCHEMA_SQL`.
  - Отдельного schema.sql нет (старый удалён 18.10, его таблицы перенесены в `SCHEMA_SQL` 21.10).
- **Хранилище R2 `bar-menu-photos`:**
  - `cocktails/<uuid>.<ext>` — фото коктейлей. Отдаются через `/api/cocktail-photo?key=…`, наружу открыт только префикс `cocktails/`.
  - `backups/<дата>/` — бэкапы.
  - Ночная уборка (cron `17 22 * * *`, 01:17 МСК) удаляет из `cocktails/` файлы без ссылок старше суток.
- **`public/`** — статика: шрифт Prata, иконки двух приложений, манифесты, `sw.js` (офлайн-помощник).
- **`BUILD_VERSION`** в `src/index.js` меняем при каждой выкладке. По нему видно, что новая версия дошла.
- **Выкладка:** push в `main` запускает GitHub Actions «Deploy Cloudflare Worker» (`.github/workflows/deploy.yml`, секреты `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`).
- **`index.html` в корне** — только переадресация со старого адреса GitHub Pages (shulya72.github.io/bar-menu) на shulya.party/menu. Pages включён с февраля; выключается в Settings → Pages.
- **`PRODUCT.md`** — продуктовый контекст для дизайн-работы.

## Локальная проверка

- Запуск: `npx wrangler@4.151.0 dev --local --persist-to .wrangler/state --port 8787`. База создаётся сама при первом запросе, тестовые данные заводятся через API сайта.
- `.wrangler/` в `.gitignore`. Перед коммитом сервер остановить и папку не добавлять.
- **Код бармена на пустой базе:**
  - задаётся ключом восстановления (он у Владимира);
  - либо записью `bar_pin` в `app_kv` локальной базы: PBKDF2-SHA256, 100 000 итераций, см. `src/barauth.js`.
- **Playwright в облачной среде Claude:** Chromium лежит в `/opt/pw-browsers`, запуск с `--no-sandbox`.

- **Данные:**
  - Как запустить: Actions → «Backup data» → Run workflow (`.github/workflows/backup.yml`).
  - Что делает: выгружает базу D1 в `db.sql` и копирует фото коктейлей в R2 `bar-menu-photos/backups/<дата МСК>/`.
  - Что в логе: только счётчики.
  - Когда запускать: перед большими изменениями (редизайн, миграции).
  - **Пока не работает** (первый запуск 18.10.2026): у токена `CLOUDFLARE_API_TOKEN` нет прав на D1, Cloudflare ответил «Authentication error 10000».
    - Владимиру нужно добавить токену права «D1 — Edit» и «Workers R2 Storage — Edit»: dash.cloudflare.com → My Profile → API Tokens → токен → Edit.
    - После этого перезапустить сценарий.
    - Секрет `CLOUDFLARE_ACCOUNT_ID` в GitHub пуст: wrangler сам находит аккаунт по токену.
  - **Ручной бэкап 18.10.2026.** Меню, рецепты и все фото коктейлей сняты с живого сайта (только GET) и отданы Владимиру архивом «VIA-Bar-меню-2026-10-18.zip». Код сайта отдан архивом «VIA-Bar-код-сайта-2026-10-18.zip».
- **D1 Time Travel.** Базу можно вернуть на любую минуту за последние 7 дней (на платном тарифе Cloudflare — 30): `wrangler d1 time-travel restore bar-menu-db --timestamp=<ISO>`. Нужен токен Cloudflare с правами D1, то есть через Actions или у Владимира.
- **Восстановление из бэкапа R2:**
  1. `wrangler r2 object get bar-menu-photos/backups/<дата>/db.sql --remote --file db.sql`.
  2. Залить в новую пустую базу: `wrangler d1 create …`, затем `wrangler d1 execute <новая> --remote --file db.sql`.
  3. Переключить `database_id` в `wrangler.toml`.
  4. Фото вернуть из `backups/<дата>/cocktails/` в `cocktails/`.

## GitHub: что осталось прибрать

- Из сессии Claude можно отправлять изменения только в свою рабочую ветку. Метки (теги) и удаление чужих веток сервер не пропускает (403).
- **Старые ветки удаляет Владимир**: GitHub → Branches, корзина у каждой ветки кроме `main` и рабочей `claude/…`. Это 37 старых веток ChatGPT-версии 4–13 октября: почти все влиты в `main` через PR #1–#33, остальные устарели (PR #4 закрыт, бэкапы ChatGPT; `backup/via-bar-original-2026-10-15` — то же, что коммит `15fc6d6`).
- Чтобы ветки не копились: Settings → General → «Automatically delete head branches».
